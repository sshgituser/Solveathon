# Qolda · клиент

Клиент кейса SerIQ E02: один веб-интерфейс для сайта, Android и настольного приложения.
Контракт анализатора — [`docs/contracts/api.md`](../docs/contracts/api.md), поведение интерфейса — [`docs/contracts/ui.md`](../docs/contracts/ui.md), дизайн-система — [`DESIGN.md`](DESIGN.md).

## Что это за приложение

Человек делает дома одно разгибание локтя, записывает его и сверяет с инструкцией. Клиент отправляет запись анализатору, показывает нейтральный результат и ведёт историю занятий на устройстве.

| Раздел | Адрес | Зачем |
|---|---|---|
| Знакомство | `#/welcome` | Карта E02 и начало проверки; обращение, рука, цель и хранение — в необязательных настройках |
| Сегодня | `#/` | Счёт за день, план, одно действие, блок «когда остановиться»; ниже показания, неделя, дневник |
| Проверка | `#/check` | Инструкция → видео → согласие → результат. Инструкцию показывает 3D-фигура |
| Прогресс | `#/progress` | Циклы по дням, регулярность, дневник самочувствия, история, отчёт для печати |
| Памятка | `#/guide` | Безопасность и общие сведения о записи и занятиях |
| Кабинет | `#/cabinet` | Локальный профиль, хранение, движение на экране, подключение анализатора, копия и удаление данных |

## Границы

- **Профиль, а не аккаунт.** Нет регистрации, сервера и пароля.
- **История по согласию.** По умолчанию данные живут в памяти вкладки. На диск они попадают, только когда человек включил сохранение. Видео не сохраняется никогда.
- **Результат не превращается в совет.** Памятка общая и не зависит от вердиктов.
- **Самочувствие отмечает сам человек.** Шкала от 1 до 5 и заметка; это не шкала боли и не оценка системы.
- **Никаких подставных ответов.** Результат показывается только из корректного ответа `seriq.v1`. Фикстуры в путь пользователя не попадают.
- **Фигура показывает категорию, а не угол.** Цифр градусов в интерфейсе нет: анализатор их не возвращает.

## Устройство кода

Без сборки и зависимостей: нативные ES-модули. Запускается с любого статического origin и внутри WebView.

```
frontend/
  index.html            оболочка страницы и CSP
  DESIGN.md             бренд, политика цвета, типографика, движение, правила 3D
  styles/
    tokens.css          все значения: цвет, шрифт, шаг, скругления, время
    base.css            сброс, типографика, фокус, отключение движения
    components.css      кнопки, панели, поля, состояния, графики
    shell.css           навигация, колонка, слои 3D-сцены
    views/<экран>.css   раскладка одного экрана, всё под классом .v-<экран>
    print.css           печатный отчёт
  src/
    main.js             запуск: язык, движение, навигация, сцена, роутер
    core/               инфраструктура, не знает про экраны
      dom.js            h()/s(): сборка DOM без innerHTML; confirmInline, flash, calm
      i18n.js           t(), формат дат из словарей, неразрывные пробелы
      router.js         hash-роутер, жизненный цикл экрана
      store.js          единственное состояние и действия над ним
      api.js            точка входа к анализатору, общий статус
    platform/           всё, что зависит от способа поставки
      profile.js        профиль local или connected и его возможности
      analyzer.js       порт анализатора и HTTP-реализация
      storage.js        порт хранения (сейчас localStorage)
    domain/             чистые функции без DOM и хранения
      stats.js          дни, серии, суммы
      tips.js           состав памятки
    stage/              3D-сцена: одна на всё приложение
      index.js          вход для экранов: initStage, createFigure, playDemo
      engine.js         рендерер и единственный цикл кадров
      mannequin.js      модель и её материалы
      rig.js            управление локтем и самопроверка углов
      dial.js           угломер, он же знак бренда
      shots.js          ракурсы камеры
      overlay.js        подписи суставов
      lighting.js       свет, тень, окружение
      three.js          единственный импорт библиотеки
      lab.js            страница разработки lab.html
    ui/                 переиспользуемые части
      controls.js       сегменты, выбор, переключатель, степпер, поле, полоса плана
      charts.js         столбцы, линия, сетка регулярности, метка состояния
      icons.js          значки и плоский знак
      arm.js            плоский рисунок руки: запас для сцены
    views/              по файлу на экран
    i18n/ru.js kk.js    тексты и названия дат
```

Правило зависимостей: `views → ui, stage → core → platform`, `views → domain`. Только `platform/` знает про `fetch` и `localStorage`. Только `stage/` знает про three.js. Экран — функция `(root, router) => cleanup`.

## 3D-сцена

- Один прозрачный холст на весь экран (`#stage`) и слой подписей (`#stage-overlay`). Экран отмечает место фигуры элементом `data-stage-slot` и вызывает `createFigure(slot, { shot, labels, side, intro })`.
- Движок кадрирует фигуру в это место через `camera.setViewOffset`, поэтому при смене раздела фигура переезжает, а не создаётся заново.
- Кадр рисуется только по событию: смена места, ракурса или позы, прокрутка, изменение окна. Фоновой анимации нет.
- Рука управляется осью, вычисленной из исходной позы модели. При запуске движок проверяет, что заданные углы совпадают с измеренными по суставам; расхождение больше 1° пишется в консоль.
- Угломер на локте считает положение стрелок по реальным суставам модели и служит знаком бренда: при первом показе он висит перед фигурой и садится на локоть.
- Без WebGL или модели в том же месте остаётся плоский рисунок из `ui/arm.js`.
- Модели и лицензии: [`assets/models/CREDITS.md`](../assets/models/CREDITS.md).

Страница `lab.html` гоняет сцену вне приложения: `?solo=1&shot=side&elbow=70&labels=1`, из консоли `lab.move("b")`, `lab.demo()`.

## Данные

```js
// seriq.prefs.v1 — не личное, сохраняется всегда
{ lang, engineUrl, model, onboarded, persist, calm }

// seriq.data.v1 — только при persist = true
{ v: 1,
  profile:  { nick, arm: "left" | "right" | null, goal },
  attempts: [{ id, ts, day, label, confidence, reason, model, modelVersion, hash }],
  checkins: [{ day, ease: 1..5, note, ts }] }
```

- `label` — `complete`, `incomplete` или `uncertain`. Пустой ответ (`no_pose`) и ошибки в историю не попадают.
- `hash` — SHA-256 байтов клипа: один физический цикл учитывается один раз. На origin без `crypto.subtle` клиент кладёт в это поле локальный отпечаток `local-fnv1a:…` (размер и края файла) только для дедупликации; это не криптографическая подпись.
- Ключи хранилища и версия контракта сохраняют имя `seriq`: это имя кейса и формата, а не продукта.

## Работа с анализатором

`platform/analyzer.js` — единственное место, где есть `fetch`. Ответ считается результатом только при `200`, `version: "seriq.v1"` и массиве `attempts`. Всё остальное — состояние с понятным текстом: `503 model_unavailable`, `engine_busy`, `invalid_video`, `duration_limit`, обрыв связи. CSP разрешает сеть только на `127.0.0.1` и `localhost`. Анализатору нужен CORS для origin клиента.

## Запуск

**Единственный адрес Web для разработки и показа:** [http://127.0.0.1:8870/](http://127.0.0.1:8870/). Это адрес на машине, где запущен движок, а не внешний сайт. Один процесс `backend.api` отдаёт UI из `frontend/`, ресурсы из соседней `assets/` и API на том же origin. Точка входа — `frontend/index.html` → `frontend/src/main.js`. Обновите страницу после правки; перезапускать движок не нужно.

Из корня проекта в PowerShell выполните `.\infra\serve.ps1`. Скрипт проверяет здоровье API и совпадение `index.html`, `main.js` и `atlas.css` с диском. Если нужный процесс уже работает, второй не запускается. При чужом процессе на порту скрипт останавливается с ошибкой и никого не отключает.

- **Для проверки с моделью A**, только если порт свободен: из корня выполните `& $Py -B -E -m backend.api --port 8870 --bundle $Bundle --artifacts $Artifacts --pose-model $Pose --private-scratch $Scratch --ffprobe $Ffprobe`. Переменные — пути к уже настроенному локальному GPU-комплекту владельца. В `GET /api/v1/health` должно быть `models.scratch: true`.
- **Без моделей**, только для проверки интерфейса: `.\infra\serve.ps1 -PreviewOnly`. Используются те же файлы, процесс слушает только loopback на `8870` до `Ctrl+C`. Ожидаемый результат отправки — `503`, без записи в историю. Скрипт не скачивает веса и не ищет свободный запасной порт.
- **Windows**: для просмотра этого же запущенного клиента используйте `Qolda.exe --attach-port 8870`. Обычный автономный запуск пакета использует `8765` — это проверка поставки, не источник веб-фронта. Android берёт ресурсы при сборке; его копии под `android/app/build/` не редактируют.
- Если в «Кабинете» остался вручную сохранённый адрес старого движка, нажмите **«Использовать адрес этой страницы»**. Адрес не меняется скрытно; история не удаляется. `8080` и `5173` не нужны для рабочего просмотра, `lab.html` и `brand.html` — стенды разработки, не альтернативные клиенты.

## Один фронт, разные способы проверки

| Где открыт клиент | Как человек выбирает источник и где идёт проверка |
|---|---|
| Web / Windows (`local`) | Файл или явный старт браузерной камеры. Адрес локального анализатора виден перед согласием; live работает на том же origin. |
| Установленный Android (`android/ondevice`) | Упаковщик добавляет `window.QoldaAndroid`. Файл выбирается системным диалогом, камера открывается только после подтверждения. Проверяет телефон; при недоступности моста UI не переключается на HTTP. Экспорт — отдельный системный диалог. |
| Браузерный `connected`, если настроен отдельно | Используется адрес сервиса из конфигурации поставки. Это не режим автономного APK. |

На Android `pick` выдаёт временный token и хеш, не файл для загрузки. Согласие на обработку не включает сохранение истории. Предварительные сообщения камеры — не результат: в историю попадает только окончательная допустимая попытка. Обычный Chrome на телефоне и установленный WebView — разные среды. [Контракт устройства](../android/ANDROID_BRIDGE.md) · [камера Web](../docs/contracts/live-camera.md) · [Windows](../desktop/README.md). Физическая проверка каждой поставки проводится отдельно.

## Что не закрыто

- Собственная инструкция — офлайн-анимация `src/ui/instruction.js` с подписями RU/KK. Это векторный рисунок, а не запись человека; на экране он так и подписан. Отдельного записанного ролика нет.
- Казахские тексты не проверены носителем языка.
- Доступность модели определяется реальным локальным анализатором. Браузерная проверка отказа без модели не проверяет классификацию, а ответ `health` не доказывает качество движения.
- Запись с камеры с обратным отсчётом не проверена на устройстве.
- Знак бренда в навигации плоский; объёмный живёт на сцене.
