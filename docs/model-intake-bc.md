## Context and Orientation

`tools/model_intake_inventory.py` смотрит только метаданные каталогов проектной рабочей копии и документированных проектных хранилищ, не идёт внутрь датасета. `tools/model_intake.py` принимает только явно переданные метаданные и не открывает медиа, архивы или вложенные ссылки из JSON. `ml/train_gpu.py` запускается отдельно только после допуска; первый GPU-граф — RTMPose Body7, второй — SLiM-производный бинарный классификатор. `subject-disjoint` означает, что ни один человек не встречается и в train, и в validation; аналогичное ограничение действует для исходных записей и семейств близких копий. Семейство `family` — один исходный записанный цикл и его копии/нарезки; канонические IDs выравниваются между источниками до разбиения.

### Контракт метаданных `qolda-e02-model-intake-v1`

UTF-8 JSON без повторяющихся ключей и дополнительных полей; не более 16 MiB на файл. Точные поля:

| Объект | Поля и значения |
|---|---|
| Верхний уровень | `schema: "qolda-e02-model-intake-v1"`, `cohort: "owned"` или `"expanded"`, `exercise: "E02"`, `group_namespace`, `attestation`, `sources`, `rows` |
| `attestation` | `owner_id: "data-owner"`, `approval_ref` и все булевы поля со значением `true`: `local_development_approved`, `canonical_groups_across_sources`, `near_duplicates_reviewed`, `one_labeled_e02_cycle_per_clip`, `public_original_excluded`, `sealed_holdout_and_quarantine_excluded`, `groups_disjoint_from_sealed_reserves` |
| Элемент `sources` | `id`, `kind` (`project_recorded` для `owned`, `approved_extension` для `expanded`), `revision`, `provenance_ref`, `rights_ref`, `consent_ref`, `annotation_ref`, `local_training_authorized: true`, `contains_patient_data: false`, `allowed_splits` (непустой список с `train`/`validation` по допуску; для `expanded` — `train`) |
| Элемент `rows` | `path` (относительно одного `$MediaRoot`; нижний регистр, `/`, безопасные ASCII-сегменты, расширение `.mp4`), `split`, `label` (целое 0/1), `sha256` (64 строчные hex-цифры), `source_id`, `subject`, `recording`, `family`, `protocol: "e02-single-cycle-v1"`, `duration_ms` (целое 1–30 000) |

`group_namespace`, `*_ref`, `id` и `revision` — непрозрачные ASCII-токены (`A–Z`, `a–z`, `0–9`, `_ . : -`, первый — буква/цифра, до 96 символов); не имена людей и не URL. `subject` / `recording` / `family` — префиксы `s-` / `r-` / `f-` и 16–64 строчные hex-цифры. Одни и те же люди и исходные объекты сохраняют одни и те же IDs в обоих наборах; эти IDs не подаются модели. Один путь/SHA не может создавать две строки. Семейство имеет одну метку, источник, раздел, человека и исходную запись; если семейство встречается в обоих корпусах, оно не является добавленным расширением. Отсутствующий допуск, неверная ссылка, конфликт групп или классов блокируют вариант.

## Concrete Steps

Команды из `C:/PRoject/Qolda`, PowerShell нативно. Все `$...` ниже — указанные владельцем приватные значения или заполненные из них переменные, не пути для поиска за пределами проекта.

### 1. Инвентаризация и приёмка метаданных

Повторить безопасную инвентаризацию без изменения сохранённого аудита:

    python -B -m tools.model_intake_inventory

Код `2` здесь означает отсутствие запиненного handoff, не ошибку выполнения. `--write-audit` создаёт один очищенный отчёт, не перезаписывает существующий. При наличии подтверждённых JSON выполнить отдельную приёмку:

    $ownedArgs = @('--metadata-dir', $MetadataDir, '--owned-name', $OwnName, '--owned-sha256', $OwnSha)
    $expandedArgs = @('--expanded-name', $ExpandedName, '--expanded-sha256', $ExpandedSha)
    python -B -m tools.model_intake @ownedArgs @expandedArgs

Если поступил только собственный корпус, можно принимать и материализовать B независимо; `--variant B` не читает расширение. Передать `--emit-dir` только после проверки допусков и только в существующий приватный каталог вне любого checkout:

    python -B -m tools.model_intake --variant B @ownedArgs --emit-dir $Stage
    if ($LASTEXITCODE -ne 0) { throw 'B intake blocked' }
    python -B -m tools.model_intake --variant C @ownedArgs @expandedArgs --emit-dir $Stage
    if ($LASTEXITCODE -ne 0) { throw 'C intake blocked' }

Выход `0` — `metadata_ready` для запрошенных вариантов; `2` — `blocked_inputs`; `3` — разрешённые метаданные, но не удалось записать приватный выход. По умолчанию запрошены оба варианта; если C заблокирован, B может быть `metadata_ready`, но общий код будет `2`. Вывод содержит причины и агрегаты без путей, IDs или SHA клипов. Сгенерированные `B.train-gpu.json` / `C.train-gpu.json` содержат пути, хэши клипов и непрямые `source_id`/`family`/`origin`, поэтому хранятся только приватно. Общая validation создаётся из одних и тех же строк закреплённого собственного манифеста в одном порядке.

### 2. CUDA-рецепт после допуска байтов

Не запускать на текущем статусе. После `metadata_ready` владелец подтверждает неизменяемый `$MediaRoot` без ссылок, отсутствие защищённых файлов и право чтения перечисленных MP4. Повторно просмотреть SHA входов по этому разрешённому snapshot; trainer проверяет каждый клип только если его кэша ещё нет. `$BWork`/`$CWork` и `$BOut`/`$COut` — новые пути вне репозитория; для каждого варианта отдельная CUDA-папка работы и отдельный выход. Не использовать старые `graphs/`, CPU-кэши или частично сформированные выходы. `$Py` — Python из отдельного согласованного CUDA-окружения Qolda, не системный CPU Torch.

Перед запуском сверить публичные model pins; эти команды предназначены для согласованного будущего прогона:

    $slimPin = 'c25c70db9ca5c1ca3715b80acbd21851fa04f4b3178e4c82f96d45492774b5bf'
    $posePin = '5c0a4bf67953e6d2ac43ce15e77dc9d5d354ae18430a47d2c5963a7bc5683e3c'
    if ((Get-FileHash -LiteralPath $SlimBase -Algorithm SHA256).Hash.ToLowerInvariant() -ne $slimPin) { throw 'SLiM pin mismatch' }
    if ((Get-FileHash -LiteralPath $Pose -Algorithm SHA256).Hash.ToLowerInvariant() -ne $posePin) { throw 'RTMPose pin mismatch' }

`$BManifestSha` и `$CManifestSha` — разные значения `trainer_manifest_sha256`, полученные из двух успешных `--emit-dir`. Закрепить каждый при выпуске и передать отдельно от соответствующего файла: нельзя вычислять ожидаемый хэш из непроверенного файла прямо перед fit. В приватной квитанции `training.exposure_by_source` даёт число допущенных, пригодных и реально использованных семейств до выбранного checkpoint для каждого источника. Эту детализацию не публиковать.

Запуск варианта B (бюджет и сетку оценки задать один раз, до запуска пары, и продублировать теми же числами для C):

    & $Py -B -m ml.train_gpu --variant B --manifest (Join-Path $Stage 'B.train-gpu.json') --root $MediaRoot --pose-model $Pose --slim-base $SlimBase --private $BWork --out $BOut --corpus-scope 'qolda-owned-e02' --manifest-sha256 $BManifestSha --steps $Steps --eval-every $EvalEvery
    if ($LASTEXITCODE -ne 0) { throw 'B training failed; retain private receipt' }

Запуск C возможен независимо от checkpoint B; для запланированного парного сравнения он обязан получить те же `$Steps` и `$EvalEvery`:

    & $Py -B -m ml.train_gpu --variant C --manifest (Join-Path $Stage 'C.train-gpu.json') --root $MediaRoot --pose-model $Pose --slim-base $SlimBase --private $CWork --out $COut --corpus-scope 'qolda-owned-e02+approved-extension' --manifest-sha256 $CManifestSha --steps $Steps --eval-every $EvalEvery
    if ($LASTEXITCODE -ne 0) { throw 'C training failed; retain private receipt' }

Без `--limit` для B/C (тренер отклоняет его для этих вариантов), без CPU/NPU fallback. Манифест B/C — только `qolda-e02-train-gpu-manifest-v2` от `tools/model_intake.py`: он содержит `source_id`, `family`, `origin` (`owned`/`expanded`) на каждую строку. Перед CUDA-инициализацией и чтением медиа тренер обязан получить `--manifest-sha256` — SHA-256 ровно тех байтов производного файла, закреплённый при его выпуске; хэш считается и JSON парсится из одних и тех же байтов. Дополнительно проверяются схема, `variant`, `corpus_scope`, оба owner-pin, разрешённые split, точный набор ключей строки и канонический путь из intake (`tools.model_intake.valid_clip_path`). Для C нужен хотя бы один допущенный `expanded/train`-клип и запрещены `expanded`-строки в validation: общая validation остаётся owned и одинаковой для B и C. Публичный E02, старый v1 и правка состава после выпуска отклоняются. B и C используют `kind='B'`, seed `602`, AdamW (`weight_decay=0.01`), `batch=8`, LR `0.00015` в блоке 7 и `0.00045` в голове; остальные тензоры заморожены. Веса классов считаются отдельно на пригодном train каждого варианта и фиксируются в отчёте. Checkpoint выбирается на общей validation по balanced accuracy, macro-F1, BCE и более раннему шагу.

### 3. Ворота сопоставимого бюджета и экспозиции

`--steps` и `--eval-every` — положительные числа, одинаковые для B и C и выбранные **до** запуска пары по априорному расчёту, а не по результатам. Минимальный разумный бюджет — один полный проход: `ceil(scorable_train / 8)`; тренер отказывается стартовать, если `--steps` меньше. Хвостовой батч не обнуляется: он доезжает как короткий батч, после чего порядок перемешивается заново.

Экспозиция считается по `family` из манифеста: тренер запоминает шаг, на котором семейство впервые попало в `opt.step`, и после выбора checkpoint сверяет его шаг с этим моментом. Если выбранный checkpoint не видел хотя бы одну требуемую семью, артефакт записывается как `<variant>-partial` (`exposure_complete=false`), а не как полноценный B/C. Семейства, у которых не оказалось пригодных строк, попадают в `unusable_families` и не считаются обученными. В `report.json`/`receipt.json` фиксируются: `budget_steps`, `eval_every`, `steps_executed`, `checkpoint_step`, `validation_checks`, `seed`, `validation_rows_sha256` (SHA-256 пар «digest клипа : label», чтобы подмена меток была видна), `class_weights`, `required_families`, `exposed_families_at_checkpoint`, `missing_families`, `unusable_families`, `expanded_required_families`, `expanded_exposed_families`, `exposure_by_origin` (допущено/пригодно/увидено по `owned` и `expanded`), `variant_claim`. Полный `C` невозможен без хотя бы одного обновления на добавленном источнике; иначе квитанция получает статус `trained_partial` и `variant_claim = C-partial`. Сводная validation-метрика и число manifest-строк не подтверждают экспозицию. Идентификаторы и связки остаются за пределами Git.

## Interfaces and Dependencies

Инвентаризация и intake используют только стандартную библиотеку Python. Intake не импортирует Torch/ORT, не запускает GPU и не открывает байты клипов. Тренер `ml/train_gpu.py` поддерживает сравнение B/C по шагам; intake сам тренер не вызывает. Версии обучающего окружения берутся из `ml/requirements-gpu.txt` и реальной CUDA-квитанции.
