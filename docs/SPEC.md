# SerIQ E02 · спецификация прототипа

> Требования хакатонного прототипа, а не подтверждение готовности.

**Сборка из исходников.** Данные, веса и платформенные артефакты подготавливаются локально по инструкциям сборки.

**Для кого:** человек выполняет один цикл реабилитационного упражнения дома; хочет свериться с инструкцией и понять, сколько попыток удалось распознать. Прототип описывает наблюдаемое движение, не состояние здоровья. [Первичное ТЗ](https://solveathon.shakarim.edu.kz/static/cases/seriq-brief-ru.pdf).

| Требование P0 | Проверяемая приёмка |
|---|---|
| Посмотреть видеоинструкцию, выбрать один ролик или записать ограниченный цикл | Есть воспроизводимая собственная/разрешённая инструкция; отказ в камере не блокирует выбор файла |
| Извлечь наблюдаемые координаты руки и проследить разгибание локтя | На реальном разрешённом видео есть временная траектория плечо–локоть–запястье и маска пропусков; отсутствие наблюдения видно |
| Сравнить два обученных классификатора одного цикла | Одинаковый split по добровольцам; A с нуля, B с исходных профильных весов; воспроизводимое обучение и повторяемые прогнозы загруженных checkpoint |
| Выдать нейтральный результат | `complete` → «Выполнено»; `incomplete` → «Проверьте инструкцию»; неуверенность и отсутствие позы — отдельные результаты, без назначений |
| Вести локальную сводку | Суммы классов и неуверенных попыток совпадают с видимым числом; повтор запроса и сравнение A/B не добавляют дубликат; есть очистка |
| Поставить три поверхности | Отдельные артефакты Web, Windows, Android; для каждой отдельная запись «собрано / запущено / пройден реальный цикл». Телефонная зависимость от ПК, если нужна, видима пользователю |
| Доказать результат жюри | README с чистым запуском, честные метрики и ограничения, открытая ссылка на разрешённую поставку, список ИИ и источников, слайды и двухминутное демо |

**P1 только после P0:** сегментация непрерывного многоповторного видео (проверить границы на ручных аннотациях, включая неполные циклы); автономный мобильный инференс с численной проверкой паритета, а не только конвертацией модели; сравнение дополнительных ракурсов. Базовый контролируемый сценарий ограничивает одну попытку отдельной записью, несколько записей образуют занятие.

**Локальное расширение клиента:** кабинет без регистрации с необязательным псевдонимом, статистика фактических занятий и добровольная отметка 1–5 «насколько легко давались движения», а не измерение боли или оценка ИИ. По умолчанию записи занятия остаются в памяти; постоянная история включается пользователем и очищается им же. Памятка остаётся одинаковой при любых вердиктах и не предписывает коррекцию. Обсуждаемый общий бекенд Web/Android не входит в проверенный локальный прототип; его контракт и права на передачу данных требуют отдельного решения.

**Расширение ТЗ команды, 25 ноября.** E02 остаётся обязательным конкурсным упражнением. В интерфейсе отдельно обозначаем **«Дополнительные упражнения»**: **E01 — поднятие предмета** и **E03 — разгибание запястья** (не E04). У каждого свой выбор режима, свои веса, порог, метрики и доступность на каждой платформе. До подтверждения модели режим помечен как недоступный для анализа; нельзя подставлять результат E02. E01/E03 не заменяют модели A/B/C для E02. Условия данных и приёмки — в [Сценарий и инструкция по запуску](SUBMISSION.md).

**Не делаем:** оценку боли/NRS, диагноз инсульта, рекомендации по лечению, оценку безопасности движения, точное медицинское измерение углов, медицинские аккаунты пациентов, облачную загрузку видео и скелетов, FHIR, прочие упражнения и iOS. В исходном наборе нет меток боли. Тест одного добровольца не подтверждает клиническую пригодность.

**Продуктовые метрики не подменяют ML:** доля оценённых роликов, число отказов по причинам, задержка на каждом реальном целевом устройстве/хосте. Не публиковать целевые цифры как измерения. Критерии жюри и какие доказательства им соответствуют — `docs/JUDGING.md`.
