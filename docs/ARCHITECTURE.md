# Архитектура Qolda / SerIQ

[Главная](../README.md) · [Результаты и сборка](SUBMISSION.md) · [Контракт API](contracts/api.md)

Qolda использует общий интерфейс и два исполнения анализатора: CUDA на ПК и LiteRT GPU на Android. Подтверждение сборки Android не означает приёмку на устройстве.

```text
Web / Windows                         Android
───────────────────────────           ───────────────────────────
Общий UI в браузере / WebView2         Тот же UI в локальном WebView
            ↓                                      ↓
HTTP на 127.0.0.1                      Нативный мост доверенного фрейма
            ↓                                      ↓
RTMPose ONNX + TCN на NVIDIA CUDA      Поза + TCN через LiteRT GPU
            ↓                                      ↓
               Результат seriq.v1 → дневник
```

## Файловый сценарий E02

1. Общий [клиент](../frontend/README.md) запрашивает выбор видео и явное согласие на локальную обработку. У продукта нет удалённого аккаунта или облачного анализатора.
2. На ПК [backend](../backend/api.py) обслуживает клиент и `/api/v1/analyze` на loopback. [Файловый адаптер](../backend/runtime.py) ограничивает контейнер, разрешение и длительность, подаёт кадры в RTMPose, кодирует наблюдаемые координаты с маской и вызывает A/TCN на CUDA. `Qolda.exe` — [WinForms/WebView2-оболочка](../desktop/README.md), которая использует этот же локальный сервер.
3. На Android системный выбор даёт мосту локальный доступ к файлу. [Нативный мост](../android/ANDROID_BRIDGE.md) выдаёт тот же результат без HTTP и без обращения к ПК. [Сборка с графами](ANDROID-FROM-SOURCE.md) отдельна от диагностического `sourcecheck`.
4. Клиент показывает нейтральную метку или отказ, не выдавая инструкцию по лечению, численный угол или диагноз. Недоступная модель либо GPU — ошибка, а не подставной результат. Пустая сцена возвращает `no_pose` без попытки.

## Поток и локальные данные

- Web/Windows передаёт временные RGB-кадры на тот же loopback origin (`start → frame → finish`). [Потоковый адаптер](../backend/live.py) хранит только необходимые наблюдения движения на время попытки. Предварительная метка не пишется в историю. Android реализует отдельный путь через Camera2. Наличие кода не подтверждает физический прогон.
- Дневник принадлежит общему клиенту. Повтор файловой попытки определяется локально. Сохранение истории выключено по умолчанию; если его включить, записи могут содержать заметки и хэш клипа. Не публикуйте экспорт дневника.
- На ПК файл обрабатывается во временном каталоге, который очищается после штатного завершения. Loopback не защищает от недоверенного локального процесса. Android-сборка не запрашивает разрешение `INTERNET`. [Объём и пределы проверки приватности](../reports/security/current-release-privacy.md).
- [E01 и E03](contracts/extra-exercises.md) — отдельные задачи и модели. Их результаты и режимы не подменяются E02.
