# Qolda: контракт камеры для общего фронта

Файловый `POST /api/v1/analyze` остаётся без изменений. Live — не загрузка фрагментов MP4: модель получает отдельные уникальные кадры и даёт обратную связь **до** завершения попытки. Одна сессия соответствует одному упражнению, начало и конец задаёт пользователь. Автоматический подсчёт серии повторений и клиническая оценка не заявляются.

## Web и Windows: только origin локального движка

Показывайте кнопку начала с пояснением локальной обработки, запросите разрешение на камеру, не запрашивайте микрофон. Камера не должна автоматически включаться при открытии кабинета. Только после согласия вызывайте следующие маршруты относительно текущего origin. Для Windows WebView2 сборка `windows-live` оставляет стандартный запрос разрешения на камеру только для `http://127.0.0.1:8765`; остальные разрешения запрещены. Никакого удалённого сервера, WebSocket, Base64, загрузки видео или сохранения кадров. `Origin` другого сайта не принимается.

| Шаг | Запрос | Ответ |
|---|---|---|
| Начало | `POST /api/v1/live/start`, `application/json`, `{}` | `version: "seriq.live.v1"`, `session` (не логировать), `max_seconds: 30` |
| Кадр | `POST /api/v1/live/frame?session=<token>&seq=1&w=320&h=240`, `application/octet-stream` | `frames`, `visible` (текущие правые локоть и запястье), `phase` (`collecting`/`ready`), `preview` (null или предварительный `seriq.v1`) |
| Завершить попытку | `POST /api/v1/live/finish?session=<token>`, JSON `{}` | окончательный `seriq.v1` или ошибка; очистить сессию, добавить только окончательный результат |
| Отменить | `POST /api/v1/live/cancel?session=<token>`, JSON `{}` | `closed: true`; ничего не добавлять в историю |

Кадр: packed RGB24, ровно `w*h*3` байт, ширина и высота 1–480; сохранять пропорции, не зеркалить вход модели даже если превью зеркальное. Последовательность начинается с 1. Не более одного запроса в полёте: не накапливать очередь, пропускать непринятые камерные кадры и отправлять самый свежий. Номер повышать после принятия кадра; при неоднозначном сетевом отказе лучше отменить попытку и начать новую. Для плавного показа оставить видеоэлемент на нативной частоте, inference — целевые 8–10 кадров/с, provisional доступен при достаточном числе кадров. `ready` означает, что для последних оценённых наблюдений модель действительно выдала предварительный ответ (`preview != null`), а **не** что пришли любые 40 кадров или упражнение выполнено. Кадры без видимой правой пары и отказы геометрической проверки сами по себе не дают `ready`. При потере правой пары `preview` сразу очищается. `visible=false` не есть `incomplete`. Процент уверенности — не вероятность правильности движения.

Захват ограничен 30 с/360 кадрами; после 30 с ещё 5 с даётся на последний `finish`, затем состояние удаляется. Ранний `finish` не фабрикует положительный результат: действует та же политика минимального покрытия, что для файла. `engine_busy` (503): подождать без очереди; `model_unavailable` (503): сообщить об отказе движка, не записывать попытку; `session_expired` (410), `frame_sequence` (409), `empty_session`/`invalid_frame`/`duration_limit` (422) различать. При уходе со страницы, скрытии вкладки, смене режима, отказе в доступе и отмене освободить media tracks, отменить незавершённый запрос и отправить best-effort `cancel`. Не сохранять черновой `preview` и не считать перекрывающиеся окна отдельными попытками.

## Android

`localhost` телефона — не ноутбук. Для автономного APK нужен локальный bridge: кадры с камерного preview идут на один worker с политикой latest-only, в проверенный ARM64 AAR, дальше — те же видимость, прогресс, предварительный и итоговый результат. Контракт состояния для фронта такой же; сетевое разрешение не нужно. Разрешение `CAMERA` при явном действии, микрофон не нужен. Запуск с физической камеры и факт установки **финальной** сборки отмечать независимо от доказанного T-017 и HTTP-реализации.

## Доказательство текущего слоя

Новый адаптер Web/Windows сохраняет между кадрами только плоские координаты и маски четырёх суставов (оба локтя и запястья; левая пара нужна для проверки неоднозначности), а не весь скелет. Невидимые точки обнуляются. При прямом запуске на RTX 5060 Ti с рабочими весами: 64 кадра разрешённого движения → первая оценка на кадре 40, 25 предварительных ответов, одна `complete`; 64 кадра существующей сцены без руки → ни одного `ready`, итог `no_pose`, ноль попыток. В обоих случаях массивы наблюдений занимали суммарно 2 304 байта полезных данных на 64 кадра (без накладных расходов Python), после `finish` оставалось ноль образцов. Приватная квитанция `live-forearm-ready-v1.json`, SHA-256 `017a428d0e3e43d9c77e53da35546b16068fc0d61c26759274e238e526300743`. Это отдельный запуск адаптера, без перезапуска существующих HTTP-процессов, не измерение Android.

### Предыдущий сквозной прогон HTTP

Отдельный локальный движок на `127.0.0.1:8870` обработал 64 RGB-кадра из разрешённого development-клипа, переданных по HTTP с частотой 10/с. Все 64 раза видна пара; первый предварительный результат на 40-м кадре, в 25 ответах он был доступен **до** `finish`; окончательный `complete`, одна попытка. Исходные кадры сервер не записывал, хранил в оперативной памяти только координаты и маски. Это реальный прогон GPU-потока с воспроизводимым источником, **не** утверждение о физической камере, готовой кнопке нового фронта или Android live E2E. Порт 8765 не перезапускали: если он обслуживает старую сборку, там новых маршрутов не будет до добровольного переключения владельцем.
