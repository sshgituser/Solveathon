**Модели и пользовательская доступность:**

На контрольной станции обе модели перечитали **все данные своих validation-разбиений** в переносимом Python; это тот же dev-участник, а не новые независимые наблюдения. E02/A прошёл полный путь HTTP → декодирование → поза → классификатор: 10/10 `incomplete`, 10/10 `complete`, ни одного отказа, пустая сцена — 0 попыток и `no_pose`. Это 21 ответ HTTP 200; временное хранилище после обработки пусто. Повторить командой из [Windows-инструкции](../../docs/WINDOWS-FROM-SOURCE.md#ограниченный-прогон-нового-комплекта-без-окна), добавив `--full-validation`. SHA агрегированной квитанции `3ef3f8430aef374bbcbcf89ce7f493caa4cfdebd877e869094d44080271d1c51`. Для [E03](../../docs/WINDOWS-FROM-SOURCE.md#4-опциональный-e03-только-новый-локальный-owner-approval) отдельно исполнен **адаптер без HTTP и UI**: 10/10 и 10/10, пустая сцена — `uncertain/low_visibility`.

- **E02 B/C:** запуск `python -B -m tools.model_intake` без предоставленных входов вернул код 2: для B нет закреплённого собственного манифеста, для C дополнительно нет манифеста расширения. Новых весов, метрик или допуска нет. [Что именно нужно владельцу данных](../../docs/model-intake-bc.md).

Не является измерением угла кисти.
